# 현재 운영 기준

정리일: 2026-11-17 KST. 현재 코드와 최신 사용자 요청을 기준으로 한다. 대체된 단계별 설계·모델 안내·검수 보고서는 제거했으며 이전 버전은 Git 이력에서 확인할 수 있다. 이 문서는 운영 서버의 적용 완료나 과거 테스트의 현재 통과를 뜻하지 않는다.

## 계정과 고객 업무

| 항목 | 현재 기준 |
|---|---|
| 활성 계정 | 직원 최대 20명, 관리자 최대 5명. 비활성 계정은 이력을 보존하고 활성 정원에서 제외 |
| 로그인 | 초기·재설정 비밀번호는 변경 전 업무 API를 차단. 변경 후 일반 업무 화면으로 이동 |
| 직원 편집 | 현재 담당 고객의 고객명·상담 정보 수정 가능. 연락처는 읽기 전용, 관리자 비고는 조회·수정 불가 |
| 관리자 편집 | 고객명·연락처·상담 정보·관리자 비고 수정 가능. 그리드에서 수동 저장 |
| 직원 저장 | 지원되는 HTTPS 환경에서 암호화 대기열·자동 저장·지금 저장 사용. 정상 활성 화면의 첫 변경 후 100초 이내 전송 시작 |
| HTTP 직원 화면 | 현장 선택·본인 고객 조회·필터 제공. 저장 지원이 부족하면 편집·저장·AI 생성 중단 |
| 고객명·연락처 | 고객명 선택·최대 100자·앞뒤 공백 제거. 연락처는 010 시작 11자리 텍스트 필수 |
| 연락처 중복 | 전체 현장의 휴지통 제외 고객과 새 중복 금지. 휴지통에만 있는 번호는 재등록 가능. 정정·복구도 재검사 |
| 업로드 | 다운로드는 고객명·연락처·고객 거주지·주택보유상황·비고·관리자 비고 6열. 기존 정확한 9열 입력 호환 유지 |
| 이력·진행 | 실제 상담 변경 저장을 진행으로 기록. 고객명·연락처·관리자 비고만 정정한 저장은 상담 진행·상담 고객 집계에서 제외 |
| 배정·회수 | 현재 배정·담당 범위·버전·세션을 서버에서 검사. 23시 기본 현장의 당일 미진행 배정 자동 회수 |

선택 목록과 이전 값 보존은 [고객 항목 선택 목록](CUSTOMER_SELECTIONS.md), 열 순서·권한은 [그리드 편집](CUSTOMER_GRID_EDITING.md), 중복 처리는 [연락처 정책](CONTACT_DUPLICATE_POLICY.md), 업로드는 [엑셀 양식](EXCEL_TEMPLATE_GUIDANCE.md)을 따른다. 이전 저장값·DB 이력·migration은 삭제하거나 새 의미로 자동 변환하지 않는다.

현재 고객 migration은 `0004_customer_selection_options`까지다. 기존 DB의 적용 여부는 대상 환경에서 확인한다. 앱·scheduler·worker는 같은 DB와 승인된 설정을 사용한다. 기존 비밀 파일·DB를 예시나 가상자료로 덮어쓰지 않는다.

직원 통화·월간 일별 실적에는 상담 `0003_performancetracking_customeractivity`가 추가로 필요하다. [기록 방법·출처·조회 범위](EMPLOYEE_PERFORMANCE.md)를 따른다. 통화·실제 방문 도입 이전의 기록을 상담 저장·방문예약으로 추정하지 않는다.

## 화면과 집계

데스크톱은 상단 메뉴를 사용하고 1199px 이하에서 메뉴를 접는다. 검색줄은 줄바꿈하고 넓은 표만 가로 스크롤한다. 제목·주요 작업·조회 상태·상세 필터·고객 이력·확인창에는 공통 UI를 사용한다. 고객 수는 명, 일정·작업은 건, 횟수는 회다. 처리 실패와 서버 응답 미확인을 구분한다. 확인창은 대상·범위·결과를 설명하고 닫으면 시작 버튼으로 초점을 돌려준다.

대시보드의 ‘다른 업무 열기’ 영역은 제거했다. 직원 화면에는 오늘 예정된 상담 고객 목록과 상담 성과·계약 현황을, 관리자 화면에는 직원별 업무량·최근 상담·통화 결과·계약 현황을 표시한다. 예시 이미지의 가상 수치를 실제 집계에 넣지 않는다.

‘오늘 받은 고객’과 ‘오늘 배정 유지’는 한국 날짜 기준 오늘 시작된 **현재 유효한 배정**만 센다. 회수·타인 재배정·휴지통 이동·미래 시각 배정은 제외하며 재배정된 고객은 최종 담당자에게만 잡힌다. 배정 작업 이력 지표는 원래 의미로 유지한다. 최근 7일 상담 고객은 실제 저장 직원별 고유 고객 수다. 반복 저장을 통화 횟수로 간주하지 않는다.

직원 오늘 상담 목록은 현재 본인 담당 고객의 오늘 미완료 재콜·오늘 방문예약을 시간순으로 표시한다. 같은 고객은 한 행으로 묶고 고객 열기로 같은 현장의 나의 DB에 연결한다. 현장 선택은 메뉴와 연결 목록에 전달하며 명시적인 ‘기본 현장 설정’만 전역 기본값을 바꾼다.

같은 현장의 갱신 실패는 마지막 성공 결과·시각을 유지하며 오류를 표시한다. 현장을 바꾸면 이전 현장 수치를 지우고 늦게 도착한 응답을 무시한다. 자세한 분모·기간·연결 필터는 [대시보드 지표](DASHBOARD_METRICS.md), 화면 및 검증 범위는 [공통 UI 기록](UI_CONSISTENCY_20261116.md)을 따른다.

## AI 설정

| 항목 | 현재 기준 |
|---|---|
| 제공자·모델 | `gemini` · `gemini-3.5-flash-lite`, 추론 low |
| 비용·전환 | 무료 등급 전용·유료 승인 $0. 유료 전환·다른 모델/공급자 자동 전환 금지 |
| 기본 상태 | `AI_ENABLED=false`, `AI_FREE_TIER_CONFIRMED=false` 유지 |
| 직원 개인 AI | 상담 정리·요약·다음 질문 합산 KST 하루 40회. 성공+진행/대기 예약 ≤ 40 |
| 공용 한도 | 프로젝트의 실제 RPD·RPM·입력 TPM·잔여량을 먼저 적용. 개인 40회는 보장 배분량이 아님 |
| 날짜 경계 | 개인 한도 KST 00시, 제공자 RPD는 미국 태평양 00시/DST. 원장 분리 |
| 관리자 공유 결과 | 주간 브리핑 일요일 접수·주 1회, 직원 코칭 대상별 하루 1회, 현장 가이드 현장별 하루 1회. 캐시 조회는 새 생성이 아님 |

이 문서의 모델명은 저장소 설정 정책이다. 공급자의 현재 모델 제공 여부·무료 등급·결제 상태·한도·잔여량은 활성화 전에 해당 프로젝트에서 확인한다. 재확인하지 않은 과거 한도값을 사용하지 않는다. 실제 호출·키 편집·활성화는 이번 정리 작업에 포함하지 않는다.

키는 서버의 보호된 0600 파일에서만 관리하고 `.env.ai.example`은 빈 값 예시로 유지한다. web/ai_worker만 AI 비밀 파일을 읽으며 scheduler/백업에는 전달하지 않는다. AI 장애·미설정 상태에서도 기본 고객관리는 동작한다. [AI 설정·키 관리](AI_ACTIVATION.md)를 따른다.

## 실행·배포·검증

로컬 실행은 [README](../README.md), 배포·백업·복원은 [운영 절차](OPERATIONS.md)를 사용한다. 기존 우분투 IP HTTPS 서버는 [HTTPS 안내](HTTPS_IP_SETUP.md)와 [업데이트 명령](SERVER_UPDATE_COMMANDS.md)을 따른다. 실제 적용 상태·인증서 발급/갱신·외부 접근·운영 성능은 대상 환경에서 별도로 확인한다.

격리 검수는 운영·개발·데모 DB 대신 매 실행마다 고유 PostgreSQL 테스트 DB와 가상 사용자·고객을 사용한다.

```sh
.venv/bin/python scripts/run_final_verification.py start
.venv/bin/python scripts/run_final_verification.py test --label local-check tests.test_stage1_evidence tests.test_acceptance
.venv/bin/python scripts/run_final_verification.py stop
```

`--label`은 재사용할 수 있지만 실제 실행 ID·디렉터리·테스트 DB는 매번 새로 만든다. `.local/verification-runs/<실행ID>/`의 `started.json`, `finished.json`, `results.json`, 구조화 이벤트 및 테스트별 산출물을 덮어쓰지 않는다. 원시 비밀번호·쿠키·인증 헤더·고객값·HTTP 본문·예외 본문·브라우저 DOM은 보존하지 않는다. 브라우저 관찰은 동작 종류·실패 여부·표준 네트워크 오류 등 허용 필드만 남긴다.

완료 기록이 없으면 미완료이며, 실패·skip·누락·소스 변경을 통과로 세지 않는다. [현재 검수 기준](ACCEPTANCE_CRITERIA.md)의 92개 항목은 같은 소스의 개별 실행 근거와 경계 검사로 판정한다. 오래된 결과를 새 소스의 통과로 재사용하지 않는다.

Docker 실기 검수는 로컬 Unix 소켓 엔진에서 별도 가상 프로젝트·볼륨·내부 네트워크로 수행한다. 엔진이 없으면 미검증이다. 비밀 파일을 빌드에 포함하지 않고 이미지 레이어·로그를 검사한다. 새 빈 PostgreSQL은 초기화 관리자와 제한된 앱 계정을 분리한다. 기존 볼륨에 초기화 스크립트를 재적용하거나 권한 문제를 0644로 완화하지 않는다.
