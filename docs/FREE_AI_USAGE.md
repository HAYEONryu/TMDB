## 적용한 한도

사용자가 AI Studio에서 확인해 알려준 프로젝트의 무료 한도를 적용했다. 결제 계정이 연결되지 않은 Free Tier임을 사용자에게 확인받았다. 공급자 계정·키의 실제 유효성을 원격 조회한 것은 아니다.

**공용500회가 먼저 소진되면 직원 개인 잔여가 있어도 새 생성을 중단한다.** 개인40회는 보장 배분량이 아니다. 관리자 요청도 같은500회에 포함한다. 500번째 예약까지 허용하며 별도의80%·90% 차단선은 없다. 이미 생성한 결과의 조회와 일반 고객관리는 계속 가능하다.

[Google 공식 한도 문서](https://ai.google.dev/gemini-api/docs/rate-limits)에 따라 한도는 API 키가 아니라 프로젝트 단위이며 TPM은 입력 기준이다. RPD는 **미국 태평양 시간 자정**에 초기화한다. 한국에서는 서머타임 중16시/그 외17시다. 직원 개인40회의 한국 자정 초기화와 구분한다. 프로젝트의 실제 한도는 AI Studio에서 확인하며 다른 프로젝트에15/250,000/500을 보편적인 고정값으로 가정하지 않는다.

## 예약·대기·실패 처리

1. 중복 요청/공유 결과를 먼저 확인한다. 신규 생성이면 DB 트랜잭션에서 공용 일일1회를 예약한 뒤 직원 개인1회를 예약한다. 서버 공용 잔여가0이면 개인 잔여와 관계없이 거절한다. 이후 검증 실패 시 두 예약을 함께 롤백한다.
2. worker가 전송 직전에 프로젝트 공용 RPM/TPM을 검사한다. 빈자리가 없으면 `RESERVED` 상태와 전송 가능 시각을 저장한다. 실제 전송·시도 횟수 증가·성공 응답을 만들지 않는다. 화면/브라우저를 닫아도 서버 대기열은 유지된다.
3. 전송할 때 공용 ‘예약1’을 ‘전송1’로 바꾸고 분당 사용량을 먼저 기록한다. 여러 worker의 동시 접수/전송도 같은 PostgreSQL 업무 잠금과 공용 행으로 직렬화한다. 같은 프로젝트의 키 교체로 사용량을 초기화하지 않는다.
4. 입력 토큰은 실제 전송할 JSON의 UTF-8 바이트 수+프로토콜 여유1024를 보수적 상한으로 예약한다. 별도 유료 토큰 계산 호출은 없다. 정상 usage가 오면 실제 입력 토큰으로 조정한다. 입력 상한이 TPM 자체보다 크면 처음부터 거절한다. 앞의 큰 작업이 기다려야 해도 남은 TPM에 들어가는 작은 작업을 처리할 수 있다.
5. 전송 전 취소·원본 삭제·일일 초기화 시점까지 미전송인 작업은 공용 예약을 반환한다. 분당 대기 작업을 기존15분 접수 만료로 폐기하지 않는다. 태평양 날짜가 넘어간 미전송 작업은 만료시키며 다음 날짜로 자동 재예약하지 않는다.
6. **이미 전송한 실패·거절·미확인 요청은 공용 RPD에서 돌려주지 않는다.** 직원 개인 성공 횟수에는 실패를 추가하지 않고 개인 예약만 반환한다. timeout/5xx는 기존UNKNOWN 처리·10분 후 보수적 종료를 유지하며 자동 재전송하지 않는다. 진행/UNKNOWN의 분당 입력 예약도 종료 전에는 해제하지 않는다.
7. 공급자429는 해당 요청을 실패로 끝내고 서버 전체를 `Retry-After`/허용된 재시도 시간에 따라 대기시킨다. 일일 한도 식별자가 오면 태평양 자정까지 중단한다. 오류 원문·키는 저장하지 않으며 다른 모델·유료 전환·가짜 성공 대체는 없다.

공용 한도는 실제 사용자 요청을 처리하는 데 최대한 사용한다. 공급자 장애·실패도 한도를 쓸 수 있고, 입력 토큰 예약은 보수적이므로 **무료 한도100% 실사용을 보장하지는 않는다**. 같은 Google 프로젝트를 다른 앱/서버에서 사용한 양은 이 DB만으로 알 수 없다. 이 서비스의 모든 인스턴스는 같은 DB·같은 프로젝트 설정을 사용해야 하며 외부 사용량 차이는 공급자429에서 공용 대기로 반영한다.

## 현재 설정과 실행

루트 `.env.ai`의 기존 키 값과 월 예산은 보존했다. Gemini 키는 `AI_GEMINI_API_KEY`, 기존 OpenAI 키는 `AI_API_KEY`로 구분하며 후자를 Google에 보내지 않는다. 파일0600·Git 제외·Docker 빌드 제외·서버 역할/로그 마스킹 경계를 유지한다.

```dotenv
AI_ENABLED=false
AI_PROVIDER=gemini
AI_MODEL=gemini-3.5-flash-lite
AI_STAFF_REASONING=low
AI_USAGE_TIER=free
AI_FREE_TIER_CONFIRMED=true
AI_FREE_PROJECT_ID=<확인한 Google 프로젝트 ID>
AI_FREE_RPM=15
AI_FREE_TPM=250000
AI_FREE_RPD=500
AI_INPUT_USD_PER_MILLION=0
AI_OUTPUT_USD_PER_MILLION=0
```

프로젝트 ID는 사용자가 제공한 값으로 실제 로컬 파일에 설정했다. 예시 파일은 다른 프로젝트가 임의 한도로 실행되지 않도록 확인false·프로젝트빈값·한도0으로 제공한다. 미확인 티어·키 누락·한도0·무료 모드의 유료 단가는 전송 전에 차단한다.

Free Tier는 Google 프로젝트의 상태다. API 요청에 무료를 강제하는 옵션이 있는 것으로 가정하지 않는다. [공식 결제 문서](https://ai.google.dev/gemini-api/docs/billing/)에 따라 결제 계정을 연결하면 유료 티어가 되므로 해당 프로젝트를 Free Tier로 유지해야 한다. [공식 가격표](https://ai.google.dev/gemini-api/docs/pricing)의 무료 티어 데이터 사용 조건도 실제 자료 사용 전에 확인한다. 이번에는 실제 고객자료를 전송하지 않았다.

새 마이그레이션은 `0006_free_provider_limits_staff40`이다. 기존30회 제약을40회로 바꾸고 공용 집계/전송 기록과 nullable 요청 필드를 추가하며 자료를 초기화하지 않는다. 기존 요청은 `usage_tier=paid`로 보존해 무료 작업으로 잘못 전송하지 않는다. 개인정보 삭제 시 고객 원문/파생 결과는 지우고 내용이 없는 집계용 카운터·토큰·시각은 보존한다.

**현재 기존 데모 웹/DB는 꺼져 있어 그대로 유지했다.** 기존 개발/데모 DB에 마이그레이션을 적용하지 않았다. 데모를 다음에 켤 때 아래 로컬 도구가 기존 DB의 마이그레이션을 적용하며 자료를 보존한다.

```sh
cd /Users/hayeon/Documents/TMDB

```

실제 무료 생성을 활성화할 때는 Google 프로젝트의 Free Tier 상태를 재확인하고 `.env.ai`의 Gemini 키와 `AI_ENABLED=true`를 설정한 뒤 `site.py restart --ai`, 별도 터미널에서 `site.py worker`를 실행한다. 이번에는 실행하지 않았다. 일반 실행 환경은 web/worker를 새 코드로 시작하기 전에 `manage.py migrate --noinput`을 적용한다. [키·활성화 안내](AI_ACTIVATION.md)를 함께 따른다.
