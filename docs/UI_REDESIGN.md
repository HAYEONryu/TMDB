# 두드림 TM 화면 개선

> 이 문서는 첫 아이보리·그린 개선 단계의 기록이다. 이후 요청에 따라 현재 전체 화면은 네이비·블루로 변경했고 팀장 그래프/통계를 추가했다. 최신 실제 화면과 집계 기준·검증은 [네이비·블루 개선 기록](BLUE_DASHBOARD.md)을 따른다.

2026-11-07, Asia/Seoul. 주 사용자인40~50대를 기준으로 복잡한 안내를 줄이고, 글자·조작부·업무 우선순위를 개선했다. 분리형 데모 **http://localhost:8010**에 반영했고 실행 상태를 유지한다. AI는 비활성이고 유료 호출0회다.

## 바뀐 화면

- **브랜드:** 모든 화면 제목·헤더·로그인·푸터를 ‘두드림 TM’으로 변경했다. 두 개의 문을 형상화한 로컬 SVG 심벌과 파비콘을 추가했다. 개발 경로·DB 이름은 바꾸지 않았다.
- **색과 글자:** 아이보리 바탕·짙은 초록·흰색을 중심으로 정리했다. 본문/고객 표16px, 일반 입력칸48px 이상, 기본 버튼46px, 로그인 버튼52px로 읽고 누르기 편하게 했다. 외부 폰트/CDN/생성 이미지는 사용하지 않았다.
- **메뉴:** 아이콘과 글자를 함께 표시하고 현재 화면을 명확히 강조했다. 모바일에서는 메뉴를 접어 숨기지 않고 격자로 표시한다. 본문 바로가기·키보드 포커스·비밀번호 변경 진입을 제공한다.
- **대시보드:** ‘계정 준비 완료’ 안내를 실제 업무 현황4개와 역할별 바로가기3개로 바꿨다. 서버의 기존 응답만 사용하고 임의의 숫자는 표시하지 않는다. 상세 현황은 펼쳐 볼 수 있다. 삭제 요청이 없으면 빈 표 대신 짧은 안내를 보여준다.
- **고객/직원 표:** 고객명·연락처·통화결과·상담 기록을 먼저 보여준다. 검색·저장·보조/삭제 동작을 구분하고 저장 상태를 또렷하게 표시한다. 원래 항목과 작업 버튼은 유지하며 표 내부에서 좌우로 이동할 수 있다.
- **로그인/보조 화면:** 로그인, 비밀번호 변경, 엑셀, 분배, 사용자, 휴지통, AI 보고서/가이드에 같은 시각 규칙을 적용했다. 메뉴·폼·업무 API의 권한은 유지했다.

## 검증

실제 Chromium에서 로그인·관리자7화면·직원3화면을 데스크톱1440px/모바일390px **22개 조합**으로 확인했다. 문서 가로 넘침0·JavaScript 오류0·외부 요청0·AI 생성POST0. 별도 UI 검사는320/390/768/1440px, 키보드 바로가기, 모바일 비밀번호 접근과 실제 집계/현장 변경도 확인했다. 물리 기기 검사나 모든 브라우저의 접근성 인증을 의미하지 않는다.

관련 브라우저 **25개 서로 다른 항목**의 통과 근거를 확보했다. 초기21개는19개 통과,1개는 테스트 도중 데모 DB 재시작이 겹친 연결 오류,1개는 로그아웃 시 로컬 기록 잔존 실패였다. 해당2개를 분리해 재검사했다. 이후 아래 경합을 재현·수정하고 영향을 받는9개 브라우저 항목을18.429초에 통과했다. 변경 영향이 없는 앞선 결과는 재사용했으며 전체25개를 한 번에 최종 소스로 재실행했다고 기록하지 않는다.

확인한 흐름은 최초 로그인/비밀번호, 현장·필터·수동 저장, 엑셀 중복, 분배·회수, 사용자 비활성화/이관, 직원 날짜·오프라인·여러 탭·로그아웃, 삭제 요청/승인, AI 선택값 저장·가이드 게시·키 비노출이다. 모든 자동 검사는 별도 `test_tm_ui_doodream` DB의 가짜 자료·테스트 전용 AI 응답을 사용하고 DB를 제거했다. 실제 OpenAI 호출은 없다.

로그아웃 검사에서 인터넷 연결 복귀의 서버 재확인과 대기값 폐기가 겹치면, 늦은 보관 작업이 삭제한 암호화 기록을 다시 쓸 수 있었다. 순서를 고정한 Node 회귀 검사로 수정 전 실패를 재현했다. 현재 대기열에 더 이상 존재하지 않는 항목은 재보관하지 않도록 검사했다. **Node19/19통과**, 새 입력·저장 중 변경·삭제 실패 시 보존 규칙도 유지한다.
