# 대시보드 지표와 연결 목록

2026-11-15 사용자 제공 대시보드 수정 요청·검수표를 기준으로 로컬 구현했다. 기존 필터 개선과 삭제 요청 행 색·직원 담당직원명 숨김 변경을 보존했다. 배정·회수·이관·상담 저장의 업무 규칙이나 DB 이력을 조회 과정에서 수정하지 않는다. 새 migration은 없다.

## 공통 기준

하나의 `/api/dashboard` 응답은 READ ONLY / REPEATABLE READ 스냅샷과 단일 서버 조회 시각 `as_of`를 쓴다. 오늘은 `Asia/Seoul` 00:00 이상 다음 날 00:00 미만이다. 현재 고객은 선택 현장의 미삭제 고객이다. 현재 유효한 배정은 현재 배정 참조가 있고 종료되지 않았으며 시작 시각이 `as_of` 이하인 배정이다.

현재 상태의 공통 조건은 `apps/customers/cohorts.py`, 유효 상담 저장 조건은 `apps/consultations/queries.py`에 있다. 카드·직원별 표·대시보드 상세 목록과 고객정보 그리드의 유입 조건이 이 조건을 재사용한다. 고객 수는 고객 ID, 완료 재콜은 일정 ID, 배정 작업은 배정 기록 ID 단위다.

## 직원 화면

| 화면 지표 / 새 API 필드 | 최종 의미 |
|---|---|
| 기한 지난 재콜 / `callbacks_overdue` | 현재 내 담당 고객 중 미완료 재콜 예정 시각 < 조회 시각 |
| 오늘 남은 재콜 / `callbacks_remaining` | 현재 내 담당 고객 중 조회 시각 ≤ 미완료 재콜 예정 시각 < 다음 날 00:00 |
| 오늘 방문예약 / `visits_today` | 현재 내 담당 고객 중 오늘 방문예약. 이미 지난 예약 시각도 포함 |
| 오늘 받은 고객 / `current_assignment_today_held` | 현재 유효한 내 배정이 오늘 시작된 고객. 회수·타인 재배정·휴지통 이동·미래 시각 배정 제외 |
| 오늘 상담 저장 / `consultation_progress.completed / total` | 오늘 받은 고객 중 현재 배정에서 내가 오늘 유효한 상담 변경을 저장한 고유 고객 / 오늘 받은 고객. 0명은 ‘오늘 배정된 고객 없음’ |
| 오늘 재콜 완료 / `callbacks_completed_today` | 선택 현장에서 내가 오늘 완료한 일정 수. 예정일·현재 담당·회수 여부를 조건으로 삼지 않는 활동 이력 |
| 현재 보유 / `held_total` | 현재 유효한 내 담당 고객 |
| 내 담당 계약 / `contracted_held` | 현재 내 담당 고객 중 현재 계약 상태가 CONTRACTED인 고객 |

두 재콜 조치 카드는 서로 겹치지 않는다. 상세 필터의 ‘오늘’은 오늘 예정 전체이므로 다른 조건이다. 카드 클릭·키보드 Enter로 직원 전용 페이지네이션 목록을 열고, 해당 목록은 최신 조회 건수·시각을 표시한다. 고객 열기는 해당 현장과 고객 전화번호 검색을 기존 나의 DB로 전달하며 기존 담당 범위·편집·저장 권한이 적용된다. 관리자 비고는 반환하지 않는다.

유효한 상담 저장은 MANUAL과 사용자가 실제 적용한 AI_APPLIED 변경이다. `changed_fields`가 고객명·연락처·관리자 비고만의 부분집합이거나 비어 있으면 제외한다. 시스템·업로드·기초 기록도 제외한다. 한 고객의 반복 저장은 1명이며 이전 배정의 저장은 현재 배정 진행으로 세지 않는다.

## 관리자 화면

상단은 미배정 고객 → 오늘 배정 유지 → 기한 지난 재콜 → 이관 필요 순이다. 미배정 고객은 현재 유효한 배정이 없는 고객이며, 실제 분배 가능 수량·작업 자격은 기존 배정 서비스가 계속 결정한다. 이관 필요는 기존 `transfer_query()`의 자격 조건을 선택 현장으로 좁혀 세고 연결 이관 목록에도 같은 현장을 전달한다.

`manager.current_assignment_today_held`는 현재 유효한 배정이 오늘 시작된 고객 수다. 직원별 `manager.staff[].current_assignment_today_held`와 합계가 같다. 비활성·관리자로 권한이 바뀐 직원에게 유효한 배정이 남아 있어도 누락하지 않는다. 직원별 표는 현재 담당·오늘 배정 유지·미진행·기한 지난 재콜을 표시하고, 재콜 기한 초과 수와 미진행 수가 많은 직원부터 정렬한다. 링크는 같은 현장·해당 직원·같은 현재 상태 조건으로 고객정보 그리드를 연다.

최근 7일 상담 고객은 실제 저장 직원별로 고객 ID를 중복 제거한 활동 이력이다. 한 고객을 두 직원이 저장하면 각 1명이다. 보존된 휴지통 고객의 과거 업무도 포함한다. 상담결과 그래프의 ‘현재 고객 상태’는 선택 현장의 현재 미삭제 고객 전체다. 오늘·금주는 그 미삭제 대상 중 오늘/월요일 00:00부터 `as_of`까지 유효한 상담 저장이 있는 고객별 마지막 저장 결과를 쓴다. 고객명·연락처·관리자 비고만의 정정은 새 집계 대상이나 마지막 상담으로 쓰지 않는다.

‘계약 상태 고객’과 계약 비율은 그래프의 같은 대상·같은 저장 스냅샷을 사용한다. 분모를 그래프 아래 표시하고, 분모가 0이면 ‘집계 대상 없음’을 표시한다. 현재 상태·상담 실적·배정 이력은 서로 다른 집합임을 각 영역에 설명한다.

## 기존 API와 상태 처리

기존 `assigned_today_unique`, `assignment_operations_today`, 최근 7일 배정 필드는 이력 의미를 유지한다. 회수·재배정·삭제 후에도 이력 수가 남는다. `assigned_today_held`는 오늘 배정 이력이 있었던 고객과 현재 보유의 교집합인 기존 지표이며 현재 배정 시작일 기준 카드에 사용하지 않는다. 기존 직원 `tm`, `callbacks_today`(오늘 예정 전체), `callbacks_past_due`(어제까지 예정), `site_contracted_total`은 호환용으로 남기고 새 UI는 위의 명시적인 상태·활동 필드를 사용한다.

고객정보 API의 `dashboard_category`는 `held`, `new_today`, `overdue`, `callbacks_remaining`, `callbacks_today`, `visits`, `unprogressed`, `contracted`를 받는다. 현장·직원 범위와 AND로 적용하고 휴지통에서는 거절한다. 적용 조건 칩에서 제거하거나 조건 초기화로 지울 수 있다. 기존 저장 보호를 거친다. 상세 필터의 기존 날짜·미입력·정확 일치·제외 기능은 유지한다.

현장은 화면당 하나만 선택한다. 카드·표·그래프·분배·이관·고객 목록에 전달하며 ‘기본 현장 설정’만 별도 명시적 PATCH 동작이다. 최초 조회·0건·갱신 실패를 구분한다. 같은 현장 갱신 실패는 마지막 성공 결과와 성공 시각을 유지하고 오류를 함께 표시한다. 새 현장을 선택하면 이전 현장 수치를 즉시 지우고, 늦게 도착한 이전 응답을 무시한다. 인증·권한 실패는 고객 상세 내용을 지운다.

## 로컬 검증

`tests/test_dashboard_current_state.py`는 회수·동일 직원 재배정·타인 재배정·휴지통·KST 자정·미래 배정·재콜 경계/완료 일정 단위·정정 제외·권한·비활성 직원 합계·기본 현장 불변을 검증한다. `tests/browser_dashboard_actions.py`는 관리자 카드·표·연결 그리드의 합계, 현장 전달, 키보드, 320px/390px/데스크톱, 갱신 실패와 이전 현장 응답 무시, 직원 상세/고객 열기를 검증한다. 기존 대시보드·배정/회수·상담·필터 테스트도 실행한다.

가상 사용자와 가상 고객, 별도 PostgreSQL 테스트 DB 및 Chromium을 사용한다. 운영 배포·실제 고객·외부 AI 요청은 이 작업에서 수행하지 않는다. 실행별 원본은 `.local/verification-runs/`에 보존한다.
