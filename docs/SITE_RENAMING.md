# 관리자 현장명 변경

2026-11-11 KST 사용자 승인으로 기존 현장명 변경 기능을 추가했다.

1. 관리자로 로그인하고 **DB 관리**에 들어간다.
2. 현장을 선택하고 선택 상자 옆의 **현장명 변경**을 누른다.
3. 새 현장명을 입력하고 **변경**을 누른다.

변경 전 미저장 고객 정보가 있으면 기존 저장·폐기·머무르기 선택부터 처리한다. 이름은 앞뒤 공백을 제거한 1~100자이며 기존 현장 생성과 같은 공백·영문 대소문자 정규화 기준으로 중복을 거절한다. 취소하면 변경하지 않는다. 다른 관리자가 먼저 변경했으면 새로고침 안내를 표시하고 덮어쓰지 않는다. 응답 유실 후 같은 이름으로 재시도하면 이미 반영된 이름을 확인하며 중복 변경 이벤트를 만들지 않는다.

현장 ID·고객정보·상담·할당·재콜과 기본 현장 설정/이력은 유지한다. 이미 열린 다른 화면의 현장 목록은 새로고침하면 새 이름을 표시한다. 직원에게는 변경 버튼을 제공하지 않으며 서버도 관리자 권한·활성 상태·세션과 화면 계정 일치를 확인한다. 이름 변경 전 발급한 현장 영구 삭제 확인은 더 이상 유효하지 않아 새 이름으로 다시 확인해야 한다.

`PATCH /api/sites/{id}`는 `name`과 목록 조회에서 받은 `expected_version`을 요구한다. 기존 Site의 수정 시각을 잠금 안에서 확인하므로 **추가 migration은 없다**. 변경 작업은 처리자·시각·종류·건수만 기존 작업 기록에 남긴다.

## 검증 기록

분리된 PostgreSQL 17 가상 DB에서 백엔드 60개와 Chromium 브라우저 4개, 총 **64개 검사 통과**. 신규 현장명 변경 9개, 기존 P2 30개, 삭제 P7 21개, 관리자 화면 4개를 확인했다. 실제 고객정보·외부 AI 요청은 사용하지 않았고 개발·데모 DB·실제 서버도 변경하지 않았다. AI 비활성 상태를 유지했다.

| 실행 ID | 결과 |
|---|---|
| `20261111T090609745187Z-41ed7c04ff9b450fa280d89baad872d8` | 64개 실행 중 63개 통과. 관리자 로그인 세션을 유지한 채 직원 로그인 폼을 찾은 신규 브라우저 검사 1개가 시간 초과. 해당 검사에서 관리자 이름 변경·중복 거절까지는 완료됐으나 직원 조회 검증은 미완료 |
| `20261111T090734148554Z-6b07c5273cf6481d8cdb270d0c913dd3` | 직원 검증을 별도 로그인 세션으로 수정한 뒤 해당 검사 1개 재실행 통과. 이름 변경 후 직원 조회와 직원 변경 버튼 미제공까지 확인 |

각 실행 중 소스 변경 없음도 확인했다. 실패 기록을 통과로 바꾸지 않고 `.local/verification-runs/<실행ID>/`에 각각 보존한다. 유효한 동일 현장의 두 이름 변경은 하나만 성공하고 나머지는 충돌하며, 두 현장을 같은 정규화 이름으로 바꾸는 경우도 하나만 성공했다. 입력 오류·중복·삭제된 현장·권한 오류·기록 저장 실패 시 기존 데이터 보존, 재시도 중복 방지, 삭제 확인 무효화, 미저장 상담 보호와 모바일 표시를 검증했다.

```sh
.venv/bin/python scripts/run_final_verification.py start
.venv/bin/python scripts/run_final_verification.py test --label site-rename \
  tests.test_site_rename tests.test_p2 tests.test_p7 tests.browser_p2
.venv/bin/python scripts/run_final_verification.py stop
```

실제 서버에는 자동 반영하지 않았다. 기존 사용자 Docker 서버는 최신 코드를 받은 뒤 [이미지 재빌드·웹/스케줄러 재시작 절차](CUSTOMER_GRID_EDITING.md#기존-docker-서버-반영)를 따른다. 기존 비밀 파일과 PostgreSQL 볼륨을 유지하며 이번 변경을 위해 DB 초기화나 AI 작업자 시작을 하지 않는다. 운영 서버의 이미지 실행·반영 결과는 별도 확인 대상이다.
