# 오늘의 TM: 최종 통화 날짜와 미완료 이월

2026-11-18 KST. 기존 `/app/employee/today`·`view=today`는 유지한다. 그리드 첫 열은 개별 통화 기록을 바탕으로 한 읽기 전용 **최종 TM 날짜**로 변경했다. 아래 TM 완료·미완료 판정은 내부 상태로 유지해 이월·회수에 사용한다. 나의 DB의 열 구성은 유지한다. [최신 열 구성·방문예정·일별 통계](DAILY_CALL_RESULTS.md)를 참고한다.

## 완료의 데이터 근거

공통 함수 `apps/customers/tm.py::with_tm_state()`를 사용한다. `ConsultationRevision`의 고객·현재 배정 ID·담당 직원 actor가 일치하고, 배정 시작 이후/조회 시각 이전의 직접 저장 또는 실제 적용한 AI 저장 중 `changed_fields`에 `call_result`가 있는 가장 최근 변경을 확인한다. 저장 시각, 동시각이면 고객 버전 순서로 판별한다. 그 변경의 결과 스냅샷이 유효하고 비어 있지 않으면 최초 통화 완료다. 부재도 완료다. 이름·연락처·비고·방문예약만의 정정과 이전 담당자/이전 배정/관리자/업로드/기초 기록은 근거로 쓰지 않는다.

통화 결과를 `-`로 비운 변경을 서버가 저장하면 더 오래된 완료 이력을 우선하지 않고 즉시 미완료로 되돌린다. 과거 배정 고객도 다시 이월하며 관리자 미완료 TM 회수도 같은 판정을 사용한다. 재입력하면 완료 조건을 다시 검사한다. 저장 실패·결과 미확인 중에는 마지막 서버 확인 상태를 유지한다. 이 변경은 기존 상담 이력이나 개별 발신·연결·실제 방문 기록을 삭제하지 않는다.

최초 통화가 완료여도 한국 날짜 내일 00:00 전까지 예정된 미완료 재콜이 있으면 `-`다. 재콜 완료의 `completed_by`, `completed_at`과 같은 시각·직원의 현재 배정 상담 이력을 함께 확인해 오늘 완료한 업무의 목록 유지를 판별한다. 취소·연기는 재콜 완료가 아니다. 최초 통화가 미완료라면 재콜만 완료해도 `-`다.

현재 최종 통화 결과나 `first_activity_at`만으로 추정하지 않는다. 별도 발신/연결 실적은 개별 통화 기록 기준이며 부재를 연결로 더하지 않는다.

## 목록과 자정

선택 현장·현재 직원의 유효 배정·미삭제 고객만 대상으로 다음을 OR로 합쳐 고객별 한 행으로 표시한다.

- 오늘 배정된 고객: 완료 여부와 무관하게 표시.
- 이전 배정의 최초 통화 완료 근거가 없는 고객: 재콜이 없어도 이월.
- 오늘까지 예정된 미완료 재콜 고객.
- 현재 배정에서 본인이 오늘 통화 결과를 기록하거나 오늘까지의 재콜을 완료한 고객: 자정까지 표시.

회수·타인 재배정·휴지통·미래 배정은 제외한다. 같은 직원에게 다시 배정해도 이전 배정 완료를 이어 붙이지 않는다. 검색·필터·페이지네이션·자동 저장·권한은 유지한다. 저장이 확인되기 전에는 완료로 바꾸지 않는다.

서버 조회 시각과 한국 날짜를 사용하며 활성 화면은 약 30초마다 날짜 전환을 확인한다. 편집·미저장·전송·미확인 작업이 있으면 목록 갱신을 미뤄 값을 보존한다. 다음 날 완료 고객은 새 배정·미완료 재콜 등 포함 조건을 다시 만족할 때만 남는다.

## 기존 이력으로 판별할 수 없는 경우

최종 결과만 있고 현재 배정·담당자와 연결된 이력이 없거나, 배정/actor/시각/변경 필드/결과 스냅샷이 부족한 경우는 `-`다. 이전 담당자의 결과와 같은 값을 재선택했지만 무변경 생략으로 새 저장 이력이 만들어지지 않은 경우도 완료를 증명할 수 없다. 개별 발신/연결 기록만으로 통화 결과를 저장했다고 추정하지 않는다.

재콜에는 배정 FK가 직접 없으므로 대응하는 현재 배정 상담 이력이 없는 과거/수동 완료 자료는 ‘오늘 이 배정에서 완료했다’는 유지 근거로 삼지 않는다. 정상 완료 서비스가 작성한 기록은 대응 이력으로 확인한다. 이력은 재작성하거나 가상 생성하지 않았다. 이 TM 상태 변경에는 새 migration이 없다.
