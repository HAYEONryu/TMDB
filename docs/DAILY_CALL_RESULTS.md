# 오늘의 TM 열 구성과 일별 통화결과

2026-11-18 KST. 기준 브랜치 HEAD `25dcdd8`의 고객 그리드·통화 기록·상담 이력·실적 집계를 확인하고 적용했다. 운영 계정이나 데이터를 사용하지 않았다.

## 오늘의 TM

업무 열은 **최종 TM 날짜 → 고객명 → 연락처 → 통화결과 → 삭제요청 → 고객 거주지 → 상담내용 → 비고 → 재콜 일정 → 방문예약 날짜 → 계약 여부** 순서다. 기존 이력·AI·통화/방문 기록과 저장 상태 기능은 이 11개 열 뒤의 작업·저장상태 열에 유지한다.

최종 TM 날짜는 `CustomerActivity(kind=CALL).occurred_at`의 한국 날짜다. 고객·현장·현재 배정 ID·현재 담당 직원이 모두 일치하는 기록 중 배정 시작부터 조회 시각 사이의 마지막 통화 시도를 사용한다. 연결·미연결·부재·확인 불가를 모두 포함한다. 기록이 없으면 `-`다. 고객 수정일·상담 저장일·재콜 완료일로 추정하지 않는다. 통화 기록을 저장하면 현재 담당 상태를 다시 확인해 날짜를 갱신하며 편집 중인 변경은 버리지 않는다.

`tm_status`는 내부 API 판정으로 유지한다. 결과 초기화·재입력·재콜·과거 미완료 이월·관리자 미완료 TM 회수는 기존 공통 판정을 사용한다. 최종 TM 날짜와 업무 완료는 서로 다른 근거다. 상담 결과만 저장한 고객은 내부 완료이면서 최종 TM 날짜가 `-`일 수 있다.

오늘의 TM에서만 주택보유상황·루트·배정일을 표시하지 않는다. 해당 데이터와 나의 DB·관리자 화면·기존 필터는 유지한다. 짧은 열의 너비를 제한하고 상담내용 340px·비고 300px을 확보했다. 긴 내용은 기존 두 번 클릭 편집기로 전체를 읽고 수정한다. 가로 스크롤은 그리드 안에서만 발생한다.

## 저장값·표시명 매핑

| 저장 코드 | 기존 선택명 | 일별 표 표시 |
| --- | --- | --- |
| `NO_ANSWER` | 부재 | 부재 |
| `DELETE_REQUEST` | 삭제 요망 | 삭제요망 |
| `REJECTED` | 거절 | 거절 |
| `NEXT_SITE` | 다음현장 연락 요청 | 다음현장 연락 |
| `INTERESTED` | 가망고객 (이전 이름 관심) | 가망고객 |

기존 `VISIT_BOOKED`의 방문예약과 이번 방문예정은 같은 예약 상태로 취급한다. 저장 코드를 바꾸거나 과거 자료를 덮어쓰지 않고 현재 선택지·필터·대시보드·보고서의 표시를 **방문예정**으로 통일했다. 실제 방문인 `VISITED`·`REVISITED`와 합치지 않는다. 월간 실제 방문고객 수는 기존 별도 `CustomerActivity(kind=VISIT).visited_on`만 집계한다. 방문예정 선택이나 방문예약 날짜 입력만으로 방문 실적을 만들지 않는다. 예약 날짜 입력과 검증은 기존 규칙을 유지한다.

삭제요망 선택은 통화결과 저장일 뿐이다. 별도 삭제요청 버튼의 확인을 거쳐야 실제 요청이 생성되고 관리자 승인 전에는 고객을 휴지통으로 이동하지 않는다.

## 일별 통계의 기록과 계산

직원 전용 GET `/api/dashboard/call-results?site_id=...&date=YYYY-MM-DD`로 조회한다. 기본 날짜는 서버의 한국 날짜이며 이전 날짜를 선택할 수 있다. 날짜·현장만 받으며 다른 직원 ID를 지정할 수 없다. 기본 오늘 조회는 한국 시간 자정 후 날짜를 갱신한다. 별도 마감·게시·집계 저장은 없다.

`ConsultationRevision` 중 다음 조건을 모두 만족하는 기록만 사용한다.

- 로그인한 직원 actor와 선택 현장의 고객이 일치한다. 현재 담당자가 바뀌었거나 회수됐어도 해당 작성자의 과거 이력은 유지한다.
- 한국 날짜 00:00부터 다음 날 00:00 전, 조회 시각까지 저장한 기록이다.
- 직접 수정(`MANUAL`) 또는 실제 적용한 AI 수정(`AI_APPLIED`)이며 `changed_fields`에 `call_result`가 있다. 업로드·기초 자료·시스템 삭제 문구·이름/비고만 수정한 이력은 결과 변경으로 취급하지 않는다.
- 같은 고객의 마지막 저장 시각, 같은 시각이면 고객 버전 순서로 한 건을 고른다. 최종 결과가 비어 있으면 제외하고 다섯 항목 외의 결과도 합치지 않는다. 고객의 현재 최종 결과는 읽지 않는다.

같은 날 부재 후 가망고객으로 바꾸면 가망고객 1명이다. 이후 날의 변경이나 재배정은 이전 날짜의 집계에 들어오지 않는다. 단순 동일값 재선택으로 새 변경 이력이 생성되지 않은 경우는 새로운 결과 기록으로 추정하지 않는다. 영구 삭제로 원본 이력이 지워진 경우에는 그 기록을 복원하거나 별도 보존하지 않는다.

오늘 통화 시도·연결·월간 콜 수의 개별 발신 횟수와 월간 실제 방문일의 고유 고객 수는 변경하지 않는다. 월간 가망은 그 날짜 상담 중 가망으로 기록된 고유 고객 수이며, 후속 2026-11-18 요청으로 **해당 기록의 배정이 수동·자동 회수되면 제외**한다. 이 문서의 일별 결과 표에는 그 회수 제외 규칙을 적용하지 않는다. 일별 표는 그날 마지막 결과별 고객 수이므로 월간 가망 집계와 단위·조건이 다르다. [월간 가망 회수 제외 기준](EMPLOYEE_PERFORMANCE.md#월간-가망의-회수-제외-2026-11-18)을 참고한다.

## 과거 조회 범위와 오류

상담 이력 도입 migration `consultations.0001_initial` 적용일 이후를 확인 가능한 범위로 사용한다. 이 날짜는 DB별로 다르며 API와 화면에 표시한다. 도입 당일이 00:00부터가 아니면 일부 기록으로 표시한다. 그 이후 기록이 없는 날은 0명이다. 도입 전 날짜, 도입 시각 미확인, 마지막 결과 변경의 스냅샷이 누락되거나 알 수 없는 값인 날은 `집계 자료 없음`이다. 과거 날짜를 입력해도 자료를 생성하거나 현재 상태로 역산하지 않는다.

API 오류는 `조회 실패`와 재조회로 표시하고 0명으로 바꾸지 않는다. 동일 범위의 마지막 성공 값이 있으면 이전 값임을 안내하며 유지한다. 현장·날짜 전환 시 오래된 응답이 새 범위를 덮어쓰지 않도록 요청 순서를 확인한다. 권한·계정 오류 때는 결과를 지운다.

새 모델이나 migration은 없다. 기존 상담 이력과 통화·실제 방문 기록의 `consultations.0003_performancetracking_customeractivity`가 적용돼 있어야 한다. 실제 운영 DB의 migration·전화 시스템·직원이 입력한 실제 통화 사실은 이번 로컬 검사 범위에 포함하지 않는다.
