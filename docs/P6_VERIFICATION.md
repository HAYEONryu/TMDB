## 3. 실패 이력과 보완

초기 서버 테스트의 stale 고객 버전·할당 시각·세션 시각 준비 오류를 수정했다. 자정을 넘겨도 실제 한국 날짜를 기준으로 가짜 시계를 고정해 고객/할당 제약과 세션 만료를 일관되게 검증한다. 기준을 낮추거나 운영 비밀번호 해시를 바꾸지 않았다.

첫 전체 회귀에서 대기열 복구 전 ‘모든 변경 저장됨’이 먼저 표시되어 검증이 실패했다. 복구 준비가 끝날 때까지 확인 중으로 표시하도록 수정했다. ACK보다 오래된 목록 응답이 기준 버전을 되돌리지 않게 보완했다. 회수 전 서버 시각 보정도 컨텍스트 수신 시각을 사용해 IndexedDB 복구 시간 때문에 늦어지지 않게 했다.

1만 건 자동 회수의 첫 전체 계측은 업무 잠금13.327초로10초 기준에 실패했다. 느린 대상 직원 DISTINCT 조인을 확인하고, 기존 공통 직렬화/잠금 순서 안에서 소규모 계정 ID 집합을 정렬 잠금하도록 바꿨다. 회수 조건·10초 합격선은 유지했다. 이후 전체227개와 성능 기준을 통과했다. 중간 실패/프로파일 로그는 `.local/p6-backend*.log`, `p6-focused.log`, `p6-tests.log`, `p6-regressions.log`에 남겼다.

## 5. 실행·직접 확인·남은 작업

직접 확인은 [README14](../README.md#14-p6-재콜통계23시-예약-확인)를 따른다. 시작 명령은 README1, 상태/명시적 실패 재시도도14절에 있다. `/healthz`200·새 API 익명401·Gunicorn2 workers의 최종 정적 자산12개 SHA/HTTP 길이 일치를 확인했다. 화면 증거 `.local/qa/p6-*`는 PC/390px에서 직접 열어 확인했다.

다음은 P7 직원 삭제 요청·관리자 승인·영구 삭제다. 이후 P8 화면 통합, P9~P12 AI·운영 보안, P13 백업/복원·종합 인수가 남았다. 기존 삭제 요청 모델·일반 휴지통 이동/복구는 보존했다. Docker 엔진 부재로 build/up·이미지 레이어는 미실행이다. 실제 운영23시까지 기다리는 검증·전원 차단·운영 HTTPS·Safari/Firefox·실제 모바일 기기·백업 복원·유료 호출·운영 배포는 하지 않았다. 작업 소유 Gunicorn/전용 PostgreSQL은 정상 종료했다.8000 포트 리스너 없음·DB 중지 상태를 확인했으며 다시 실행하는 명령은 README1에 있다.
