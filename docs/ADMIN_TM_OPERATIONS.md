# 관리자 삭제 요청 일괄 승인·미완료 TM 회수

2026-11-17 KST. 현재 브랜치 `532ea8a`의 기존 동작에 추가했다. 이전 ‘오늘의 TM’ 작업의 미완료 검증도 먼저 마쳤다. 운영 계정·데이터는 사용하지 않았고 배포·커밋은 하지 않았다.

## 고객정보 삭제 요청 일괄 승인

- 관리자 대시보드 승인 대기 목록에서 요청을 선택하고 **선택 요청 일괄 승인**을 누른다. 미선택·진행 중에는 비활성화한다. 기존 개별 승인도 유지한다.
- 현재 페이지(최대 50건) 선택이며 페이지를 바꾸면 선택을 지운다. API는 중복 없는 1~100건을 허용한다. 확인창은 전체 선택 수·현장별 수와 휴지통 이동 결과를 설명한다.
- 서버는 기존 `apps/customers/deletions.py::approve()`를 재사용한다. 관리자·로그인 상태를 확인하고 각 요청의 최신 상태를 검증한다. 승인된 고객의 현재 배정을 종료하고 기존 규칙대로 휴지통으로 이동하며 상담·재콜 이력을 보존한다.
- 이미 승인·종료·삭제된 요청은 제외한다. 결과에 **승인 N건 · 제외 M건**과 항목별 현장·고객·연락처·제외 사유를 표시한다.
- 항목마다 승인과 진행 상황 저장을 하나의 트랜잭션으로 묶는다. 일부 DB 오류가 발생해도 다른 항목의 확정된 승인은 유지하고 실패 항목은 남긴다. 같은 일괄 요청으로 재시도하면 실패·대기만 처리한다. 승인·제외 항목은 다시 처리하지 않는다.
- 서버와 브라우저의 기존 멱등성·결과 미확인 복구 경로를 사용한다. 중복 클릭·동시 제출·응답 유실 후 새로고침에도 같은 요청 ID로 확인한다. 보관 기간은 기존 7일이다. 이후 임의 재실행하지 않고 최신 목록을 확인한다.

## 미완료 TM 회수

- DB 분배·회수의 기존 **선택 직원의 오늘 배정 회수**를 유지하고 별도 **미완료 TM 회수**를 추가했다.
- 선택 현장과 직원(또는 전체 활성 직원)의 현재 유효 배정 전체를 검사한다. 과거 배정도 포함하며 직원 화면의 검색·필터·페이지·표시 행 수를 받지 않는다.
- 직원 목록과 같은 `apps/customers/tm.py::with_tm_state()`의 `PENDING`만 대상으로 한다. 별도 미완료 판정식을 두지 않는다. 현재 배정에서 해당 직원이 실제로 통화 결과를 변경한 상담 이력이 있어야 최초 통화 완료 근거가 된다. 부재도 TM 완료다. 오늘까지 미완료 재콜이 있으면 다시 미완료다. 상세 기준과 과거 이력의 한계는 [오늘의 TM](TODAY_TM.md)을 참고한다.
- 확인창에 현장·한국 날짜·직원별 대상 수·합계를 표시한다. 확인 대상의 고객·배정·직원 ID, 한국 날짜 및 표시 이름을 서버 서명으로 묶고 10분간 유효하게 한다.
- 확정 시 관리자·현장·직원·현재 배정·TM 상태를 다시 검사한다. 같은 수라도 대상이 바뀌거나 자정이 지나면 회수하지 않고 최신 인원을 표시해 다시 확인받는다. 직원이 통화를 완료하거나 담당자가 바뀐 고객도 이 검사로 보호한다.
- 기존 `end_locked(..., MANUAL_RECALL)`을 재사용해 현재 배정만 종료하고 미배정으로 돌린다. 상담·재콜 이력은 보존한다. 성공 응답의 재시도는 기존 결과를 돌려주며 이후 새로 생긴 배정을 회수하지 않는다.
- 처리 후 분배 화면의 직원 목록·가용 고객 수와 관리자 대시보드를 갱신한다. 직원이 화면으로 돌아왔을 때 담당 목록도 다시 조회하되 편집·미저장·전송 중인 작업을 버리지 않는다.
