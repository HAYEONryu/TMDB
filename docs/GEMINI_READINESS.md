# Gemini 연결 준비 검수

> **후속 Lite 전용 변경:** [최신 환경 점검](LITE_ENV.md)을 따른다. Gemini3.8 지원을 제거하고 `.env.ai` 중복변수4개를 삭제했다. 아래 복수모델/변수 설명은 이전 단계의 기록이다. 키 보존·AI 비활성 유지, 이번 DB 없는22개 검사 통과.

2026-11-07, Asia/Seoul. 최신 요청을 기준으로 **Gemini 3.8 Flash를 우선 준비**했다. 실제 외부 AI 호출·유료 작업·고객자료 전송·배포는0회다. 기존 개발/데모 DB는 변경하지 않았고 현재 AI는 비활성이다.

## 기준과 기존 구현

프로젝트의 v2.0 설계서19~20장, P13 검증 기록, 최신 진행27절까지, 서버·worker·브라우저 코드를 읽었다. 저장소/적용 하위 경로와 상위 디렉터리에서 적용되는 AGENTS.md는 발견되지 않았다. 원 설계의 직원30회와 관리자5명 미만 조건보다 최신 사용자의 **직원40회·직원20명/관리자5명 검증** 지시를 우선했다. 설계서 원문은 수정하지 않았다.

기존 DB 큐·권한·ReportSlot·캐시·선택 적용·비용 원장과 OpenAI 어댑터를 유지했다. 모의 어댑터는 TESTING·별도 테스트DB·명시적 테스트 설정에서만 실행한다. 운영 공급자 실패를 모의 성공으로 바꾸지 않는다.

## 공식 확인과 모델 설정

- [Gemini 3.8 Flash](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash): 정확한 ID는 `gemini-3.8-flash`, 정식 모델이며 구조화 출력·추론low/medium/high를 지원한다. 실제 계정에서 이 모델에 접근 가능한지는 호출하지 않아 미검증이다.
- [GenerateContent REST](https://ai.google.dev/api/generate-content): 기존 지원 API인 `POST /v1beta/models/{model}:generateContent`를 사용한다. 현재 문서에서 Legacy 경로로 분류되며 이번에는 기존 큐와 단일 요청 구조를 유지했다. `systemInstruction`, 단일 user 입력, `responseFormat.text`의 JSON 스키마, `thinkingConfig=LOW`, 합산 최대 출력 상한을 사용한다. 도구·검색·외부 URL 실행·샘플링·스트리밍·명시적 캐시는 요청하지 않는다.
- 같은 문서의 `usageMetadata`에서 prompt/candidates/thoughts/cached/total을 구분한다. total은 입력+출력+생각이며 생각을 출력에 이중 합산하지 않는다. 모델·종료 사유·JSON 형태·토큰 합계·근거·현재 권한을 검증한다. 잘린 응답·거절·틀린 모델·잘못된 JSON/usage를 성공으로 저장하지 않는다.
- [오류 안내](https://ai.google.dev/gemini-api/docs/generate-content/api-errors): 400/401/403/404/413/422는 확정 실패, timeout/5xx/불명확한 usage는 UNKNOWN으로 보수적 처리한다. 무료429는 서버 전체 대기 및 일일 소진 시 태평양 자정까지 중단한다. 무제한 재시도·유료 전환·다른 모델 자동 대체는 없다.

이번 공식 검수 우선 대상은 `AI_PROVIDER=gemini`, `AI_MODEL=gemini-3.8-flash`다. 최종 로컬 파일은 사용자 후속 선택대로 `gemini-3.5-flash-lite`를 유지한다. 검토한 다른 ID `gemini-3.5-flash-lite`도 **운영자가 모델을 명시적으로 설정할 때만** 같은 어댑터로 사용할 수 있다. OpenAI도 기존 명시적 설정 경로를 보존한다. 미검토 모델 ID는 전송 전에 차단하며 가장 가까운 모델로 대체하지 않는다. 직원3종/관리자3종은 모두 같은 AI_CONFIG→제공자 선택→worker 경로를 사용한다. 직원·관리자 추론은 기존 승인된low를 유지했다.

## 파일 전용 비밀값

실제 키는 프로젝트 루트 **`.env.ai`**의 `AI_GEMINI_API_KEY`에만 입력한다. 기존 OpenAI 키 항목 `AI_API_KEY`는 OpenAI 설정에서만 사용한다. 두 키 항목의 값은 보존했으며 출력하지 않았다. 키 없는 경우에도 일반 고객관리·모의 테스트는 동작한다.

실제 자격증명은 **파일에서만** 읽는다. 같은 이름의 프로세스 환경변수는 인증에 사용하지 않는다. 모델/제공자/한도 같은 비밀이 아닌 설정은 서버 환경변수로 재정의할 수 있다. `AI_ENV_FILE`은 이름이 `.env.ai`인 보호된 서버 파일 경로만 지정한다. web/ai_worker만 로딩하고 management/scheduler/test는 실제 키 파일을 읽지 않는다. 파일0600·로그 마스킹·브라우저 응답 allowlist를 유지했다.

`.env.ai.example`은 모든 대입값을 빈 값으로 만들고 설명을 주석에 적었다. 이를 실제 파일에 덮어쓰지 않는다. `.gitignore`/`.dockerignore`의 실제 환경 파일·비밀 디렉터리 제외와 예시 파일 예외를 확인했다. 현재 Git 추적/인덱스/조회 가능한 이력 및 소스/자산/로그의 현재 키 일치 여부는 비밀값을 표시하지 않는 별도 감사로 기록한다. 이미 공개/추적된 키가 확인되면 공급자에서 폐기·재발급한 뒤 추적 해제 및 협의한 이력 정리가 필요하다. 이번 작업은 Git 이력을 강제로 변경하지 않는다.

Compose는 `.env.ai`를 env_file로 펼치지 않고 **web/ai_worker에만 `/run/ai/.env.ai`로 읽기 전용 마운트**한다. scheduler·proxy·DB에는 전달하지 않는다. 이미지 빌드 컨텍스트에는 실제 파일을 포함하지 않는다. 컨테이너 UID10001이0600 파일을 읽을 수 있도록 호스트 파일 소유권/마운트 권한을 준비해야 한다. 권한 문제를 해결하려고0644로 공개하지 않는다. 실제 Docker 엔진·이미지/레이어 검증은 아직 미검증이다.

## 사용량·공유·전송 기록

직원은 한국 날짜 하루 **성공40회**이며 진행 중 예약을 포함해 성공+예약≤40을 강제한다. 세 기능 합산이며 실패는 성공 횟수에 넣지 않는다. 실제 전송 여부가 불명확한 작업도 완료/확정 만료 전까지 예약을 유지한다.

직원 개인 성공 횟수, 논리 작업의 claim/시도, **외부 전송 시작 표식**, 재시도 시작 횟수를 분리했다. 네이티브 어댑터의 사전 검증 뒤 실제 transport를 실행하기 직전에 원자적으로 표식을 기록한다. 연결 직후 끊긴 요청이 공급자에 도달했는지까지 증명하는 표식은 아니다. 같은 시도의 중복 전송은 차단한다. 전송 시작/재시도 집계는 관리자 usage API에 별도로 반환한다. 모의 Foundation 어댑터는 실제 전송 표식을 만들지 않는다.

관리자 결과는 공유한다. 주간 브리핑은 조직GLOBAL+월요일 기준 주1회(일요일 접수), 코칭은 직원+한국 날짜 하루1회, 가이드는 현장+한국 날짜 하루1회다.5명 관리자가 동시에 눌러도 동일 슬롯의 작업/성공본을 반환한다. 결과 GET·게시·기존 결과 반환에는 새 외부 호출이나 비용 예약이 없다. 가이드 검토/게시 승인과 직원의 AI 추천 기본 미선택·선택 필드만 저장 규칙을 유지했다.

## 무료 한도: 직접 확인할 값

[AI Studio](https://aistudio.google.com/)에서 **프로젝트/결제 티어 → Usage/Rate limits → 정확한 모델**을 선택해 다음을 확인한다. [공식 한도 설명](https://ai.google.dev/gemini-api/docs/rate-limits)에 따라 프로젝트·모델별 값이며 API 키 수를 늘려 별도 한도로 계산하지 않는다.

| 설정 | 입력할 값 |
|---|---|
| `AI_FREE_PROJECT_ID` | 해당 키의 Google 프로젝트 ID |
| `AI_FREE_TIER_CONFIRMED` | 결제 미연결 Free Tier를 확인한 경우에만true |
| `AI_FREE_LIMITS_MODEL` | 한도를 확인한 정확한 모델 ID. `AI_MODEL`과 같아야 함 |
| `AI_FREE_RPD` | 해당 모델/티어의 하루 요청 한도 |
| `AI_FREE_RPM` | 분당 요청 한도 |
| `AI_FREE_TPM` | 분당 **입력** 토큰 한도 |

이전 Lite의15/250,000/500을3.8에 복사하지 않았다. 작업 중 외부 편집된 로컬 파일을 확인한 후 사용자에게 물었고, **사용자는 Lite 설정 유지를 선택**했다. 현재 로컬 모델은 `gemini-3.5-flash-lite`, 한도 값은 이전 사용자 제공15/250,000/500이며 **확인false·AI 비활성**으로 보존한다. 실제 활성화 전에 AI Studio에서 이 값을 다시 확인해야 한다.3.8을 선택하면3.8의 한도를 따로 확인하고 모델 바인딩도 함께 변경해야 한다. 실제 값이 들어오면 기존 공용 예산/예약/대기열이 작동한다. 무료 비용0은 확인한 무료 프로젝트/모델·한도·요금제 설정이 모두 맞을 때만 허용한다. API 옵션으로 계정의 무료 과금을 강제할 수 있다고 가정하지 않는다.

신규 접수 시 직원/관리자를 합친 서버 공용 일일1회를 먼저 예약하고, 전송 전 RPM/TPM을 확인한다. 진행 중/UNKNOWN은 입력 상한을 미리 차감한다. 분당 여유가 없으면 DB 대기열에서 기다린다. 실제 usage로 입력 예약을 조정한다. 미전송 취소/날짜 만료는 반환하고, 전송된 실패/미확인은 공용 RPD를 반환하지 않는다. 공용 소진 시 개인 잔여가 있어도 중단한다.

개인40회는 KST 자정, 공급자 RPD는 **미국 태평양 시간 자정** 기준이다(서머타임에 따라 한국16시/17시). 외부 앱이 같은 프로젝트를 사용한 양은 이 DB만으로 알 수 없어 공급자429를 공용 대기로 반영한다. 실제 무료 한도100% 사용이나 장애 없는 실행을 보장하지 않는다.

## 비용과 두 예산

입력은 직원최대16000/관리자32000토큰, 출력+생각의 **공유 상한**은2048/4096토큰이다. 전송 JSON의 UTF-8 크기+프레이밍 여유를 검사하고, 무료 TPM은 이 보수적 입력 상한으로 미리 예약한다. 유료 모드는 입력 최대치와 공유 출력 상한의 최대 비용을 먼저 예약한다. 단가·모델·티어를 산정/검증할 수 없으면 전송하지 않는다.

[공식 Standard 가격](https://ai.google.dev/gemini-api/docs/pricing)에서3.8은2026-12-31까지100만 토큰당 입력USD0.75/출력3.75(생각 포함), 이후1.50/7.50이다. 유료 설정이 현재 검토 단가와 다르면 차단한다. Lite는0.30/2.50이다. 현재 로컬 파일의 무료 요금제0/0을 유료 단가로 바꾸거나 실제 유료 호출을 하지 않았다.

| 예산 | 설정·원장 |
|---|---|
| 조직 월 예산 | `AI_MONTHLY_BUDGET_USD`, 접수한 KST 월의 AIBudgetMonth. 성공/실패 과금+미결 예약 포함 |
| 테스트 누적 예산 | `AI_TEST_BUDGET_USD` + 고정 `AI_TEST_BUDGET_SCOPE`, AITestBudget. 월이 바뀌거나 worker가 재시작해도 누적. 범위명을 바꾸면 다른 원장이므로 캠페인 중 유지 |

두 예산은 서로 다른 원장으로 같은 요청 비용을 각각 검사한다. 둘 중 하나가 부족하면 접수를 롤백한다. scope/단가/예산이 잘못되면 차단한다. 성공·알려진 과금 실패는 실제 입력·출력·생각·캐시 사용량으로 정산하고, 미확인 요청은 자동 재전송 없이 기존10분 후 예약 비용을 보수적으로 확정한다. 종료 후 늦은 추가 과금도 두 원장에 반영한다. 무료 요청은 확인된 단가0으로 비용0이며 공용 요청/토큰 한도를 별도로 소모한다. 실제 청구서·외부 앱 사용액의 절대 상한을 보장하는 기능은 아니다.

현재 테스트 누적 예산은 **USD0**, scope는`gemini-connection-preflight`다. 월 예산 기존USD5는 보존했다. 실제 유료 연결 검사를 시작하려면 별도 승인과 명시적 테스트 예산 변경이 필요하다. 이번에는 바꾸지 않았다.

## 실행·재시작

이번에는 중지된 기존 데모/개발DB를 그대로 두었다. 새 migration `0007_separate_test_budget`은 테스트 누적 원장·요청 연결·전송 시작 표식을 추가한다. 일반 환경은 새 web/worker를 시작하기 전에 기존 DB에 `manage.py migrate --noinput`을 적용한다. 초기화 명령은 사용하지 않는다.

키 없는 기본 데모(외부 AI 비활성):

```sh
cd /Users/hayeon/Documents/TMDB
.venv/bin/python .local/demo/site.py start --no-ai
# 이미 실행 중이면 restart --no-ai
```

이 로컬 도구는 분리된 데모DB에 마이그레이션을 적용한다. 실제 전송을 향후 승인받아 활성화할 때만 `.env.ai`에 위 확인값·Gemini 키·예산을 입력하고 `AI_ENABLED=true`로 바꾼다. 기존worker는 Ctrl+C로 종료한 뒤:

```sh
.venv/bin/python .local/demo/site.py restart --ai
# 별도 터미널: 같은 데모 DB/설정의 AI worker
.venv/bin/python .local/demo/site.py worker
```

이 단계부터 대기 작업이 실제 Google로 전송될 수 있다. 끄려면 worker Ctrl+C → `.env.ai`의AI_ENABLED=false → `site.py restart --no-ai`. 모두 종료는 `site.py stop`. 일반 설치의 worker 명령은 `.venv/bin/python manage.py run_ai_worker`이며, 앱 재시작 방식은 사용하는 Gunicorn/서비스 관리자에 따른다. Compose 변경은 web/worker 재생성이 필요하지만 이번에는 빌드·배포하지 않았다.

## 검증과 남은 사항

별도 PostgreSQL17/55434와 폐기용 테스트DB, 합성 키·가짜 Gemini 응답·차단된 외부 transport를 사용했다. 새 코드의 실제 키를 테스트로 전송하지 않는다. 직원20명+관리자5명의25개 동시 예약→직원20작업+공유 가이드1작업, 다중worker 동시2개,5명 관리자의 세 보고서별 공유/재조회, 월 전환 테스트 예산·실패/UNKNOWN정산을 확인했다. 이는 실제25명 운영 SLA/생성 품질 검증은 아니다.
