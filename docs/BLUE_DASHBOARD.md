# 네이비·블루 전체 화면과 팀장 통계

2026-11-07, Asia/Seoul. 참고 이미지의 네이비 왼쪽 메뉴·블루 강조·밝은 본문·요약 카드 구성을 **실제 코드에 반영**했다. 브랜드는 ‘두드림 TM’이다. 분리형 데모 **http://localhost:8010**에서 실행 중이며 실제 AI 호출0회다.

## 화면 적용

공통 레이아웃/색상으로 로그인·비밀번호, 팀장/직원 대시보드, 고객관리, 엑셀, 분배·회수, 사용자, 휴지통, AI 보고서·근거 기록·팀 가이드에 적용했다. PC에서는 왼쪽 메뉴, 좁은 화면에서는 상단 메뉴 격자를 제공한다. 본문·표16px, 큰 입력/버튼, 현재 메뉴·키보드 포커스 구분은 유지했다. 직원에게는 자기 고객/업무만 표시하고 팀 전체 통계는 제공하지 않는다.

직원 버전 실제 캡처: [대시보드](../outputs/ui-blue/employee-dashboard.png), [고객관리](../outputs/ui-blue/employee-customers.png). 팀장: [대시보드](../outputs/ui-blue/manager-dashboard.png), [영업 진행 보기](../outputs/ui-blue/manager-progress.png). ## 팀장 대시보드 사용법과 집계 기준

1. 상단 **현장** 또는 **상담결과 비율 → 현장별로 선택**에서 현장을 선택한다. 두 선택창은 서로 연동되며 현황·직원 그래프·분배/진행 표가 해당 현장 기준으로 갱신된다.
2. **상담결과 비율 → 조회 기간**에서 `전체 기간 / 금주 / 오늘`을 선택한다. 금주는 월요일부터 일요일까지다. 기간은 상담결과 비율에 적용하고, 직원별 누적 상담기록은 최근7일 기준을 유지한다.
3. **직원별 DB 현황**에서 `DB 분배 수량 / 영업 진행 현황`을 선택한다. 직원 이름을 누르면 해당 직원의 고객관리 목록으로 이동한다.

| 항목 | 집계 기준 |
|---|---|
| 오늘 할당 DB | 한국 날짜00시부터 조회 시점까지 해당 현장에 배정한 **고유 고객 수**. 같은 고객의 재분배는 상단 숫자에서 중복 제외. 회수/휴지통으로 이동한 고객의 남아 있는 배정 이력도 포함 |
| 직원별 분배 수량 | 직원별 오늘/최근7일 고유 고객 수, 최근7일 배정 횟수, 현재 보유를 구분. 같은 고객이 여러 직원에게 배정되면 직원별 합계가 현장 전체 고유 수와 다를 수 있음 |
| 최근7일 직원별 누적 상담기록 | 오늘 포함7개 한국 날짜의 저장 이력을 **실제 작성 직원별**로 합산. X축 직원, Y축 기록 수. 같은 고객을 여러 번 실제 변경 저장한 이력도 포함 |
| 기록 제외/포함 | 업로드·도입 기준·시스템 삭제 문구·미래 이력 제외. MANUAL 및 직원이 선택해 저장한 AI_APPLIED 포함. AI 생성만 한 것은 상담 이력이 아님 |
| 전체 기간 상담결과 | 휴지통 제외 현재 고객 전체의 현재 통화결과. 미입력도 표시 |
| 금주/오늘 상담결과 | 해당 기간에 실제 상담 변경을 저장한 현재 고객의 **기간 내 마지막 결과를 고객당1회** 집계. 이후/미래/시스템 변경으로 덮어쓰지 않음. 이번주는 월요일00시~다음 월요일00시 미만, 조회 시점 이후 자료 제외 |
| 영업 진행 | 현재 보유 고객 중 **현재 할당에서 상담 변경을 한 번 이상 저장**한 고객. 이전 담당자의 진행을 새 담당자에게 이어 붙이지 않음. 통화 연결/계약 성공과 같은 의미로 사용하지 않음 |
| 영업 진행 표 | 직원별 현재 보유·진행·미진행·진행률, 현재 상담결과별 수, 계약 상태가 ‘계약’인 수 표시 |
| 비활성/권한 변경 직원 | 최근 활동이나 현재 보유가 있으면 별도 표시해 이력을 누락하지 않음. 직원 그래프는 실제 작성자 기준이며 현재 담당자에게 과거 기록을 이전하지 않음 |

비율의 모수는 기간에 따라 달라지므로 차트 중앙 고객 수와 하단 기준을 함께 표시한다. 데이터가 없으면0·빈 그래프로 표시하며 임의의 예시 수치로 대체하지 않는다. 영구 삭제로 제거된 원본 이력은 집계에도 남기지 않는다. 원본 개인정보/메모는 통계 응답에 포함하지 않는다.

## 구현·검증

서버는 `apps/operations/dashboard_reports.py`에서 PostgreSQL 집계를 수행한다. 기존 `/api/dashboard` 응답을 유지하면서 관리자 전용 `manager`와 `result_period=all|week|today`를 추가했다. 직원의 기간/팀 통계 요청은403이며 다른 직원 정보를 반환하지 않는다. 반복 파라미터·잘못된 기간은422, 통계 조회는 기본 현장 설정을 변경하지 않는다. 기존 읽기 스냅샷 트랜잭션 안에서 조회한다. 신규 집계 함수는 직원 수와 무관한 그룹 쿼리 수≤8 검사를 통과했다. 기존 호환 집계까지 포함한 전체 API 쿼리 수의 상한을 의미하지는 않는다.

차트는 로컬 SVG로 구현해 외부 CDN·차트 라이선스/구독·AI 생성 호출이 없다. 직원이 많으면 그래프/표 내부를 좌우로 이동할 수 있다. 빈 값·조회 실패·현장/기간 빠른 전환에도 이전 기간 차트를 새 결과처럼 표시하지 않도록 처리했다.

- **신규 서버 검사10개**, 기존 통계 호환2개, 관련 **Chromium 브라우저22개**의 서로 다른34항목에 대해 통과 근거를 확보했다.
- 마지막 실행은 **25/25통과,54.000초**(브라우저22+서버3), 실행 중 소스 불변. 새 통계의 변경 없는 앞선 통과 검사는 반복하지 않았다.
- 처음에는 꺼진 데모 DB를 켠 뒤 실행했다. 기간 테스트의 고정 시각/세션 만료와 Playwright 이후 동기 ORM fixture 오류를 수정해 실패 항목만 재검사했다. 이 중간 실패를 최종 통과로 숨기지 않고 원시 로그에 보존했다.
- 한국 시각·월/일/연도 경계, 고객별 마지막 결과, 중복 분배, 실제 작성자, 비활성/권한 변경, 현재 담당자별 진행, 휴지통, 직원 권한, 원문 비노출, 빈 현장, 조회 실패, 모바일, 실제 저장·엑셀·분배·승인·AI 선택값/키 비노출을 검사했다.
- 로그인·비밀번호·관리자/직원·가이드·기간/진행 보기의 **31개 실제 화면/상태** 확인. 가로 넘침0·JS오류0·외부 요청0·AI POST0. 물리 모바일·모든 브라우저 인증을 뜻하지 않는다.

## 현장·기간 선택 후속 수정 — 2026-11-07

‘현장 전체’라는 기간 문구를 없애고 그래프 안에 실제 현장 선택창을 추가했다. 상단 선택과 양방향으로 연동하며 기간은 전체 기간/금주/오늘로 분리했다. 조회만으로 기본 현장을 저장하지 않으며, 선택한 현장에 자료가 없으면 빈 결과를 표시한다. 서버 집계와 직원 권한은 변경하지 않았다.

변경 영향을 받는 브라우저2개를 별도 PostgreSQL `test_tm_graph_filters`에서 재검사해 **2/2통과(4.802초)**했다. 현장 선택 양방향 연동, 기간 전환, 직원 현황 탭, 조회 실패 시 이전 차트 제거를 확인했다. 변경 없는 기존 통과 검사는 반복하지 않았다. 검사 소스 SHA는 `01dee7f3341791db4b67ae2491109171e7dd15df821610b46f6c91ff1f291646`이며 실행 전후 동일했다. 근거: `.local/graph-filter-verification.json`, `.local/demo/graph-filter-tests.log`. 기존34개 전체를 이 SHA에서 다시 실행했다는 의미는 아니다.

실행 중인 데모의 변경 화면을1440px/390px에서 추가 확인했다. 가로 넘침·JS 오류·외부 요청·AI POST는 모두0이다. 근거: `.local/qa/graph-filters/review.json`. 웹/정적 파일을 최신 코드와 일치시켰으며 데모는 계속 실행 중이다.
