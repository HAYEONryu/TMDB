# 직원 작업 버튼·재콜·AI 사용 준비

2026-11-13 KST. 현재 사용자 요청에 따라 직원 작업 칸을 간소화했다. 실제 고객자료·외부 AI 호출·비밀 파일 변경·서버 배포는 수행하지 않았다. 무료 Gemini 3.5 Flash-Lite·유료 승인 $0·AI 비활성/무료 미확인 유지 기준은 [현재 운영 기준](CURRENT_OPERATING_BASELINE.md)을 따른다.

## 화면 사용

직원 작업 칸은 **이력 / 삭제 요청 / AI 도움** 세 버튼이다. ‘작업’ 헤더 위에 마우스를 올리면 각 기능과 재콜 완료 방법을 설명한다. 헤더에 키보드로 초점을 맞춰 읽을 수 있는 설명도 제공한다. 작업 열의 최소 폭은 950px에서 300px로 줄였다.

- **이력**: 저장된 상담 변경·재콜 기록을 필요할 때 조회한다. 조회만 하며 새 이력을 만들지 않는다.
- **삭제 요청**: 관리자에게 고객 삭제 승인을 요청한다. 승인 전 고객은 유지된다. 중복 요청·미저장 행 처리·실패 재시도 규칙은 유지한다.
- **AI 도움**: 아래 세 생성 기능의 차이와 기존 결과 조회를 한 창에서 선택한다. 창을 열거나 기존 결과를 읽는 것만으로 생성 요청·사용 횟수가 발생하지 않는다.

| AI 기능 | 용도 | 고객정보 변경 |
|---|---|---|
| 항목 정리 (이전 AI 상담 정리) | 상담 문장을 정돈하고 통화결과·재콜·방문 등의 항목을 제안 | 현재 값과 비교해 사용자가 고른 항목만 저장 대기열에 반영 |
| 핵심 요약 (이전 상담 요약) | 상담 핵심·관심과 우려·약속·확인 사항을 요약 | 읽기 전용 |
| 다음 질문 | 다음 통화에서 확인할 질문 제안 | 읽기 전용 |
| 기존 AI 결과 보기 | 저장된 결과를 다시 확인 | 새 생성이나 횟수 차감 없음. 오래된 결과의 적용 제한은 유지 |

## 재콜 완료

작업 칸의 별도 ‘재콜 완료’ 버튼을 없애고 **재콜일정 셀 안에 완료 체크**를 넣었다. 미완료 재콜이 있는 행에만 표시한다. 실제 재콜을 마쳤을 때 체크하면 이 행의 미저장 내용을 먼저 저장하고 재콜을 완료한다. 다른 행의 저장 대기 시간은 바꾸지 않는다.

상담내용 저장·날짜 경과만으로 실제 재콜 완료 여부를 판단하지 않는다. 날짜를 비우는 것은 **일정 취소**이며 완료와 구분한다. 완료 요청의 응답이 끊기면 기존 결과 확인/재시도 안내를 사용한다. 같은 완료 요청을 재시도해도 새로 등록된 재콜을 완료하지 않는다. 회수·이관 이후의 옛 할당 요청은 서버에서 거부한다.

## 이력과 용량

이력 버튼을 제거해도 이미 저장된 DB 용량은 줄지 않는다. 이력은 충돌 비교·늦은 저장 거부·사용자 변경 확인·AI 근거에 쓰이므로 원본을 지우지 않았다. 실제 운영 DB의 이력 용량·서버 메모리는 이번 작업에서 측정하지 않았으며, 이력이 무한히 늘어도 용량 문제가 없다는 뜻이 아니다.

필요할 때만 한 페이지 50개씩 조회하는 방식은 유지한다. 상담 이력 응답에서는 화면에 필요한 **변경된 항목의 변경 전/후 값**만 내려보내고, 중복된 전체 상담 원문 필드는 빼며 해당 원문 컬럼도 별도로 로드하지 않는다. 과거 도입 기록처럼 변경 필드가 비어 있는 기록은 저장된 기준 값으로 표시한다. 원본 revision·상담 원문·재콜 DB는 유지한다.

가상 상담문을 반복해 저장한 뒤 재콜 날짜만 수정한 이력 한 행을 동일한 UTF-8 JSON 방식으로 비교했다. 이전 형식 **25,921B → 변경 후 378B (98.54% 감소)**였다. 이는 해당 가상 사례의 응답 내용 비교이며 HTTP 압축·헤더, 운영 평균, DB 저장량 감소, 서버 RSS/성능 측정값이 아니다. 수치는 검수 산출물 `history-response-size.json`에 보존했다.

## AI 준비가 부족할 때

이전에는 AI 설정/연결·개인/공용 한도 등이 준비되지 않으면 개별 생성 버튼이 비활성화됐다. 현재는 ‘AI 도움’에서 기능 설명과 실제 서버가 반환한 준비 사유를 확인할 수 있다. 기능을 선택했을 때 조건이 부족하면 **alert와 화면 안내만 표시하고 생성하지 않는다.**

1. 해당 고객의 상담내용에 관심·질문·약속 등 실제 상담 내용을 입력한다. 고객명·연락처만 등록된 상태는 생성하지 않는다.
2. 해당 행을 저장한다. 저장 실패·오프라인 상태에서는 AI 작업을 접수하지 않는다.
3. 서버가 현재 담당자·할당 ID·고객 버전과 입력 범위를 다시 확인한다. 빈 상담내용, 100개 이력/직원 입력 바이트 상한 초과 등은 사용 횟수 예약 전에 거부한다. 너무 긴 입력은 핵심 상담내용을 간결하게 정리하고, 이력 상한은 원본을 삭제하지 말고 관리자에게 분석 범위 확인을 요청한다.
4. 이름·연락처·관리자 비고만 정정한 이력은 상담 분석 자료에서 제외한다. 과거 고객명 가림과 도입 기준 상담 기록은 보존한다.
5. 관리자는 무료 등급·현재 프로젝트 한도 확인, 서버의 키/모델/파일 권한과 AI 활성화 상태를 준비해야 한다. 설정 파일 연결/0600 권한·비활성·키/모델 미설정·무료 미확인·한도 미설정에 따라 구체적인 안내를 표시한다. 개인 40회, 공용 RPD 소진, RPM/TPM 대기, 이미 진행 중인 작업도 구분한다.

직원 기능에는 별도 엑셀 업로드나 현장 지식 등록을 의무화하지 않는다. 현재 기능이 실제 사용하는 저장된 상담정보가 필요하다. 공개 AI 요청에는 기존 서버 전처리와 개인정보 가림을 계속 적용한다.

준비 조회는 읽기 전용 API이며 공급자를 호출하거나 예약 원장을 만들지 않는다. 실제 접수 API도 상담내용 조건을 독립적으로 검사하므로 화면 검사를 우회해 빈 상담을 접수할 수 없다. 준비 확인 직후 담당자가 변경된 경우도 실제 접수의 권한 검사로 거부한다.

이번 작업은 AI 활성화 승인이 아니며 `.env.ai`를 수정하지 않았다. 실제 서버에서 비활성화된 정확한 설정 사유는 배포 후 화면 안내로 확인해야 한다. 무료 확인·현재 한도 확인 없이 true로 바꾸지 않는다. AI 작업자는 [활성화 조건](AI_ACTIVATION.md)에 따라 웹과 같은 이미지 버전으로 관리한다.

## 기존 HTTPS 서버 반영

이번 수정에는 새 migration이 없다. 현재 적용된 DB·비밀 파일·HTTPS를 유지하며 AI를 새로 활성화하지 않는다. 기존 고객 migration이 미적용인 서버는 [전체 업데이트 안내](SERVER_UPDATE_COMMANDS.md)를 먼저 따른다. 아래는 기존 HTTPS 서버의 이미지 갱신이다. 저장 중인 작업을 마친 뒤 실행한다.

```bash
cd /root/TMDB &&
git pull --ff-only &&
bash scripts/compose_https.sh build web scheduler &&
bash scripts/compose_https.sh up -d --no-deps --no-build --force-recreate web scheduler &&
bash scripts/compose_https.sh ps
```

HTTPS 브라우저를 강력 새로고침하고 작업 버튼·헤더 도움말·재콜 완료 체크·AI 준비 사유를 확인한다. 이 절차는 AI 작업자를 시작하지 않는다. 실제 서버 이미지 빌드/배포 성공, 운영 DB 용량·메모리/성능, 외부 Gemini 연결·현재 무료 한도는 로컬 검수 결과로 통과 처리하지 않는다.
